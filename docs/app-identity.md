# App identity avatar bundles

Each preset has a self-contained directory at `public/avatars/<id>/` containing character-only transparent `still.png` (512 × 512), alpha VP9 `new-session.webm`, and transparent `new-session.apng` (canonical in-app animation across browsers). Motion is square, silent, and 24 fps. A browser can advertise VP9 support yet composite its alpha as opaque; the app therefore uses APNG, retaining WebM only for verified external consumers. Never fall back to opaque MP4: it would restore a baked-in background. `icon.png` is the separate opaque install/favicon asset; its backdrop is intentional only for platform icons, not in-app avatars. `server/shared/appIdentity.ts` is the canonical preset manifest. The service worker precaches the application shell and default still, but does not precache the dynamic install manifest or all avatar animations. An avatar used while online is cached on demand for later offline visits; alternates not yet viewed require a connection. The avatar cache namespace is derived from sorted artwork paths and bytes at build time; a changed bundle replaces only older avatar caches on service-worker activation (other caches remain untouched). The public sign-in page renders the effective saved identity in its initial HTML, so it never preloads Current Pi before showing another selected avatar. The public `/identity/config.json` and avatar assets are intentionally readable without login so the sign-in page can display branding; do not put secrets in identity names or images. The same still and animation bundle supplies the gallery, new-session surface and public sign-in page. Reduced-motion preference and failed playback show the still image. Original source bundles are backed up at `.pi/web/artifacts/avatar-sources/original/` for reversible regeneration. The 204×204 source videos have genuine pose changes (for example, Robot receives its star midway through motion); do not force an exact still match before the final frame. The matte pipeline combines character-scale U2Net, BiRefNet, stationary-frame entry segmentation, and localized topology restoration from original RGB. Source-versus-matte review sheets are at `.pi/web/artifacts/avatar-sources/raw-matte-detail.png`.

To add a preset, prepare a square still and individual square motion clips in both formats under a new directory, add the ID and label in `server/shared/appIdentity.ts`, and run the identity asset tests, typecheck, build and full test suite. Verify both codecs and first/last frames visually. Existing alternate presets were extracted from a 608 × 608, 3 × 3 source sheet by resampling the whole frame to 612 × 612 before cropping even 204 × 204 cells, avoiding fractional chroma crop offsets. That source sheet is not shipped or referenced at runtime.

Custom avatar uploads currently accept **only a PNG still**; they do not supply motion. The new-session view falls back to the still for custom avatars. The spring animation remains the application's independent fallback when avatar motion is unavailable; adding a preset does not change that behavior.
