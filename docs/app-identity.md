# App identity avatar bundles

The **tracked, canonical artwork** for each of the nine presets is in `public/avatars/<id>/`: transparent 512×512 `still.png`, transparent single-play `new-session.apng` (about 24 fps), and separate 512×512 `icon.png` for installation/favicon use. `server/shared/appIdentity.ts` is the preset manifest. APNG is the only in-app motion format: browsers that advertise VP9 can still composite its alpha opaquely. Do not substitute opaque MP4 for in-app artwork. The original 204×204 source videos and matte project are **not included in this repository**, so pixel-identical regeneration from those sources is not reproducible by a fresh clone; local `.pi/web/artifacts/` backups are not project inputs. Edit the tracked PNG/APNG assets directly (retaining all frames, frame timings and alpha), review every frame, and commit the resulting canonical files. To verify a changed preset, run `file public/avatars/<id>/{still.png,icon.png,new-session.apng}`, `ffprobe -v error -show_streams public/avatars/<id>/new-session.apng`, and the browser animation/offline tests. The website's old promotional videos live separately under `website/assets/`, not in the app package.

The service worker precaches the shell and the default Current Pi still (verified in the built `dist/sw.js` by the package smoke); it does **not** precache the dynamic install manifest or every animation. Artwork used online is cached on demand for offline visits; alternates never viewed still require a connection. The avatar cache namespace derives from sorted artwork paths and bytes at build time, replacing only obsolete avatar caches on activation. The public sign-in page renders the saved identity in initial HTML; the main app leaves its artwork empty until saved settings arrive instead of flashing Current Pi. The public `/identity/config.json` and avatar assets are readable without sign-in for branding; do not put secrets in names or artwork. Reduced-motion preference and failed animation show the still. Custom uploads are still-only (normalized to 512×512 PNG) and apply immediately without saving name drafts. Preset selection and name edits require Save. Reset asks for confirmation, saves default identity and then deletes the old upload only when the saved identity revision still matches; a cleanup failure is reported explicitly. Switching to a preset does not delete an uploaded file, so users can switch back.

Every bundled and custom install icon is 512×512. The manifest only advertises that actual size with `purpose: "any"`; custom art has no verified maskable safe zone. A preset's `icon.png` is deliberately opaque where its platform backdrop requires it, never on the in-app still or APNG.
