# App identity avatar bundles

The **tracked, canonical artwork** for each of the nine presets is in `public/avatars/<id>/`: transparent 512×512 `still.png`, transparent single-play `new-session.apng` (about 24 fps), and separate 512×512 `icon.png` for installation/favicon use. `server/shared/appIdentity.ts` is the preset manifest. APNG is the only in-app motion format: browsers that advertise VP9 can still composite its alpha opaquely. Do not substitute opaque MP4 for in-app artwork. The original 204×204 source videos and matte project are **not included in this repository**, so pixel-identical regeneration from those sources is not reproducible by a fresh clone; local `.pi/web/artifacts/` backups are not project inputs. Edit the tracked PNG/APNG assets directly (retaining all frames, frame timings and alpha), review every frame, and commit the resulting canonical files. To verify a changed preset, run `file public/avatars/<id>/{still.png,icon.png,new-session.apng}`, `ffprobe -v error -show_streams public/avatars/<id>/new-session.apng`, and the browser animation/offline tests. The website's old promotional videos live separately under `website/assets/`, not in the app package.

The service worker precaches the shell and the default Current Pi still (verified in the built `dist/sw.js` by the package smoke); it does **not** precache the dynamic install manifest or every animation. Artwork used online is cached on demand for offline visits; alternates never viewed still require a connection. The avatar cache namespace derives from sorted artwork paths and bytes at build time, replacing only obsolete avatar caches on activation. The public sign-in page renders the saved identity in initial HTML; the main app leaves its artwork empty until saved settings arrive instead of flashing Current Pi. The public `/identity/config.json` and avatar assets are readable without sign-in for branding; do not put secrets in names or artwork. Reduced-motion preference and failed animation show the still. Ordinary image uploads are still-only (normalized to 512×512 PNG); instance-local custom packages may additionally include a separate `fab.png` for the floating launcher (otherwise the still is used) and a transparent single-play APNG using the same playback, still fallback and reduced-motion path as presets. Both apply immediately without saving name drafts. See [custom avatars](custom-avatars.md) for package/API and storage details. Preset selection and name edits require Save. Reset asks for confirmation, saves default identity and then deletes instance-owned generation packages only when the saved identity revision still matches; a cleanup failure is reported explicitly. Potentially shared legacy `pi-web-avatar.png` files are retained, as stated in the confirmation; their ownership cannot safely be inferred from this settings file. Switching to a preset does not itself remove generation packages.

Bundled install icons and normalized single-image uploads are 512×512. Custom packages may supply icons from 1×1 to 2048×2048; the manifest advertises their actual validated IHDR dimensions with `purpose: "any"`. Custom art has no verified maskable safe zone. A preset's `icon.png` is deliberately opaque where its platform backdrop requires it, never on the in-app still or APNG.
