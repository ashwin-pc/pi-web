# Optional local Qwen Image 2.1 tool (macOS)

This **opt-in Pi extension** runs Qwen Image 2.1 flavors using an isolated ComfyUI installation; it is not registered by pi-web. **Model names and preferences belong to your local JSON config, not the shared tool.** The checked-in [`config.example.json`](config.example.json) illustrates two choices only; edit/copy it outside the repository and choose any aliases, default, compatible Qwen 2.1 BF16 or GGUF diffusion weight filenames, text encoder/VAE, optional LoRA, and sampling settings. Model weights, Python environment and local config are not shipped. This is a Qwen 2.1 workflow, **not an arbitrary image-model/architecture loader**: another architecture with different nodes, conditioning, latent layout or VAE requires a separate implementation.

## Install and configure

1. Provision your trusted isolated Qwen 2.1 ComfyUI under a directory containing `venv/bin/python`, `ComfyUI/main.py`, Pillow and PyTorch. Set `PI_IMAGE_RUNTIME_ROOT` **before starting Pi**, e.g. `export PI_IMAGE_RUNTIME_ROOT="$HOME/.local/share/qwen-image-2.1-comparison"` (adjust for your installation).
2. Copy `custom_nodes/pi_qwen21/` into `$PI_IMAGE_RUNTIME_ROOT/ComfyUI/custom_nodes/pi_qwen21/` as a unit with this extension and runner. ComfyUI must provide `TextEncodeQwenImage21`, `UNETLoader`, `LoraLoaderModelOnly`, `KSampler`; GGUF profiles additionally require `UnetLoaderGGUF`. This node implements Qwen's 64-channel latent, Viggle flow sigmas and MPS-safe VAE temporal zero-padding.
3. Copy `config.example.json` to a private, writable file, edit `defaultModel` and `models`, then set `PI_IMAGE_CONFIG=/absolute/path/to/your-image-config.json`. You can freely rename aliases, remove/add variants, select compatible filenames and adjust `sampling` per variant. `model.loader` is `UNETLoader` (safetensors) or `UnetLoaderGGUF` (GGUF); model assets are filenames within ComfyUI `models/diffusion_models`, `models/text_encoders`, `models/vae`, and optional `models/loras`. Standard sampling accepts 1–128 steps, `cfg`, `sampler`, optional `scheduler` and `denoise`; `viggle-flow` uses the fixed four-step Qwen/Viggle schedule and should be paired with a compatible Viggle LoRA. Values are validated; ComfyUI finally determines whether particular weights/options are compatible. Verify weight provenance/licenses yourself.
4. Put `index.ts`, `config.ts`, `runner.py` together in a personal Pi extension directory, e.g. `~/.pi/agent/extensions/image/`, or load `index.ts` with `pi --extension /path/to/index.ts`. Pi provides `typebox` and `@earendil-works/pi-coding-agent`. **Do not** install `config.example.json` unchanged as a mandatory policy. Remove/disable previous tool registrations (`comfy-image-generate`, `comfy-image-edit`, `qwen-image`) yourself if replacing them, then `/reload` or start a fresh session. This PR does not change any personal settings, active sessions, deployed runtimes or server defaults.

## Use

`image({prompt:"A watercolor lighthouse"})` uses the **locally configured** `defaultModel`. `image({model:"my-detailed-qwen",prompt:"..."})` selects any locally configured profile; there is no fixed enum in the tool schema. Omit the input image to generate, or use `image_path` plus up to two `reference_image_paths` to edit/compose. Batch: `jobs:[{prompt,seed,width,height}, ...]` with an optional shared prompt; all jobs use the selected profile and run sequentially, stopping inference between jobs. Top-level image/seed/dimensions cannot mix with jobs. Generation defaults to 1024×1024; edit canvas follows the primary image aspect ratio. Paths resolve against session cwd; width/height are 256–2048 in multiples of 32. To change weights/sampling mid-batch, make separate calls or define additional local profiles.

Each job starts/stops a loopback-only ComfyUI process and stores copied inputs, workflow, config-derived request (including weight filenames/prompts/paths), logs and results under `.pi/web/artifacts/image/<run-id>/`. These can contain private data; remove them yourself. Cancellation sends SIGTERM to the runner, which terminates the ComfyUI process group, escalating to SIGKILL if needed. macOS `memory_pressure` (≥25% free) and active-ComfyUI process checks run before loading weights; there is **no cross-session lock**, so simultaneous calls can race. Other platforms fail closed on the macOS memory preflight.

## Verification

From repository root: `node --import tsx --test examples/pi-web-extensions/image/test.ts` and `python3 -m unittest discover -s examples/pi-web-extensions/image -p test_runner.py`. The Python tests build workflow graphs without weights and test torch padding parity if torch is installed (use the isolated runtime's Python). No inference is required. Prior smoke images in `evidence/` came from the original local runtime, not a fresh-install validation of the configurable package.
